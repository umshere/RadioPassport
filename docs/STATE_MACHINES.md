# App workflow and state inventory

The audit started from production `main` at `3f125ae`. The tables link to source and nearby tests. Coverage varies by workflow and browser.

## Decision

Make request ownership explicit at the boundary where a discovery result can tune the player. Home and Desk share [one request lifecycle](../app/hooks/useStationRequest.ts). Existing models already cover many local UI transitions, so their owners stay in place. This keeps the same player store, global audio element, and route contracts.

| Event | Transition and effect |
|---|---|
| Start a discovery request | Replace the prior request, abort its browser fetch, and mark the new request pending. Home uses this for Surprise and sentence interpretation. Desk uses it for Surprise and submitted catalog searches. |
| Edit the query, choose a Home hour, board a station, change transport state, or leave the route | Invalidate the outstanding request. The pending indicator clears when the control remains mounted. |
| Current request succeeds or fails | Accept its outcome once. The caller owns the result, empty, or error presentation and any resulting station selection. |
| Superseded request settles | Ignore its result and error. Only the current request can clear its own pending state. |

For listeners, a late result can no longer replace a newer choice in these flows. For developers and agents, the code exposes the same start, cancel, and settle rules in one place and keeps the page-specific effects in their respective owners.
